# Автоматизация тестов (UI & API)

В этом файле я описал, как устроена автоматизация в моем пет-проекте, какие технологии использовал и как запустить тесты у себя локально. 

Изначально проект задумывался как чисто ручной, но теперь я добавил слой автотестов: покрыл UI интернет-магазина и ключевые запросы к API.

---

## Что использовал 

* **Язык:** Python 3.13
* **Фреймворк для тестов:** Pytest
* **Для UI тестов:** Playwright (синхронный вариант `sync_api`)
* **Для API тестов:** Requests
* **CI/CD:** GitHub Actions
* **Для работы с переменными:** Python-dotenv

---

## Как устроены папки в репозитории

Все автотесты лежат в корне проекта и разделены на две папки:
* `ui_tests/` — тут лежат тесты для интерфейса сайта **DemoBlaze**.
* `api_tests/` — тут лежат тесты для проверок бэкенда.
* `conftest.py` — здесь настроена общая фикстура для запуска и закрытия браузера.
* `pytest.ini` — базовые настройки Pytest.
* `requirements.txt` — список библиотек, которые нужно установить.

## Как и что я тестировал

### 1. Тестирование интерфейса (UI)
Для UI я выбрал **Playwright**, потому что он быстрый и современный. Тесты проверяют основные действия пользователя на сайте [DemoBlaze](https://demoblaze.com):
* Успешный вход в аккаунт и проверку на неправильный пароль.
* Выбор категорий товаров (ноутбуки, телефоны, мониторы) и работу фильтра.
* Добавление товара в корзину.

### 2. Тестирование Бэкенда (API)
> **Почему тесты API написаны для ReqRes.in?**  
> Изначально я хотел тестировать API самого DemoBlaze. Но в процессе ручного тестирования через DevTools понял, что их бэкенд для учебных автотестов подходит плохо: база данных часто сбрасывается, токены генерируются нестабильно, и сложно проверять негативные сценарии. 
> Поэтому для API-тестов я взял стабильный учебный сервис [ReqRes.in](https://reqres.in). На нем я написал проверки для создания пользователя, успешной регистрации, авторизации и проверку на ошибку, если забыли ввести пароль.

## ⚙️ Настройка GitHub Actions (CI/CD)

Я настроил автоматический запуск тестов в GitHub Actions (файл `.github/workflows/run-tests.yml`). Тесты запускаются сами каждый раз, когда я делаю `git push` в ветку `main`.

**Что интересного реализовано:**
1. **Авто-переключение режима браузера:** Чтобы тесты не падали на сервере GitHub (где нет обычного экрана), в `conftest.py` написана проверка среды. Когда тесты идут на GitHub, браузер запускается в скрытом режиме (`headless=True`), а когда я запускаю их у себя на компьютере — браузер открывается как обычно (`headless=False`), чтобы можно было глазами увидеть ход теста.
2. **Безопасность (Секреты):** Пароль для тестов не светится в открытом коде. Я скрыл его в настройки репозитория (GitHub Secrets) и передаю в код через переменные окружения.

## Как запустить тесты у себя на компьютере

Если нужно запустить тесты локально, сделайте следующее:

1. **Склонируйте проект и зайдите в папку:**
   ```bash
   git clone https://github.com
   cd qa-pet-project
   ```

2. **Установите нужные библиотеки:**
   ```bash
   pip install -r requirements.txt
   ```

3. **Скачайте браузеры для Playwright:**
   ```bash
   playwright install
   ```

4. **Добавьте пароль:**
   Создайте в корне проекта обычный текстовый файл с названием `.env` и впишите туда строчки ниже:
   ```env
   MY_PASSWORD = cityslicka
   DB_PASSWORD = 1111
   DB_USER = daniil_1331
   ```

5. **Запустите тесты:**
   * Запустить вообще всё (и UI, и API):
     ```bash
     pytest 
     ```
   * Запустить только API-тесты:
     ```bash
     pytest -m "api" 
     ```
   * Запустить только UI-тесты:
     ```bash
     pytest -m "ui"
     ```
